Verifiquei o material que você mandou, e o “não puxa dados” no PDDEinfo quase sempre acontece por um destes 3 motivos:

Você está esperando JSON, mas o endpoint devolve HTML
No PDDEinfo, boa parte das telas (ex.: escola/consultar, entidade/situação, etc.) retorna página HTML renderizada no servidor, não uma API JSON “limpa”.
👉 Então fetch(...).json() vai falhar ou vir vazio — você precisa fetch(...).text() e parsear o HTML (Cheerio, BeautifulSoup, etc.).

CORS (se você está chamando direto do front-end)
Se você tentar chamar https://www.fnde.gov.br/pddeinfo/... direto do browser (React/Next etc.), é comum bloquear por CORS.
✅ Solução: criar um proxy no seu backend (sua API) e o front chama a sua API.

Encoding / charset (latin1 / iso-8859-1)
Essas páginas frequentemente vêm em ISO-8859-1. Se seu código assume UTF-8, pode dar string “quebrada” e seu parser não encontra os seletores, parecendo “sem dados”.
✅ Solução: baixar como arrayBuffer e decodificar como latin1 (iconv-lite).

O que dá pra tratar como “API” de verdade (JSON)

Pelo que você já tinha identificado nos requests, existe sim endpoint JSON (exemplo típico):

GET /pddeinfo/pddeinfo/corp/get-municipio/sg_uf/{UF} → JSON (lista de municípios)

Esse você pode consumir como JSON normalmente.

Exemplo pronto (Node/Express) — proxy + decode + parse
1) Endpoint JSON (municípios)
import express from "express";

const app = express();

app.get("/api/pddeinfo/municipios/:uf", async (req, res) => {
  const { uf } = req.params;

  const url = `https://www.fnde.gov.br/pddeinfo/pddeinfo/corp/get-municipio/sg_uf/${encodeURIComponent(uf)}`;

  const r = await fetch(url, {
    headers: {
      "User-Agent": "Mozilla/5.0",
      "Accept": "application/json,text/plain,*/*",
      "X-Requested-With": "XMLHttpRequest",
    },
  });

  if (!r.ok) return res.status(r.status).send(await r.text());

  // aqui normalmente é JSON mesmo
  const data = await r.json();
  res.json(data);
});

app.listen(3000);

2) Endpoint HTML (ex.: escola/consultar) — vira “API” via scraping
import express from "express";
import * as cheerio from "cheerio";
import iconv from "iconv-lite";

const app = express();

app.get("/api/pddeinfo/escolas", async (req, res) => {
  // repasse os params que você já usa: ano, co_escola, cnpj, co_esfera_adm, sg_uf, co_municipio_fnde...
  const params = new URLSearchParams(req.query);

  // alguns formulários do FNDE só retornam resultado se existir o “consultar=Consultar”
  if (!params.has("consultar")) params.set("consultar", "Consultar");

  const url = `https://www.fnde.gov.br/pddeinfo/pddeinfo/escola/consultar?${params.toString()}`;

  const r = await fetch(url, {
    headers: {
      "User-Agent": "Mozilla/5.0",
      "Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8",
      "Referer": "https://www.fnde.gov.br/pddeinfo/pddeinfo/escola/consultar",
    },
  });

  if (!r.ok) return res.status(r.status).send(await r.text());

  // decode latin1/iso-8859-1 (muito comum nessas páginas)
  const buf = Buffer.from(await r.arrayBuffer());
  const html = iconv.decode(buf, "latin1");

  const $ = cheerio.load(html);

  // 👇 ajuste o seletor conforme a tabela real da página (id/class)
  // exemplo genérico: pegar linhas de tabela
  const rows = [];
  $("table tr").each((_, tr) => {
    const cols = $(tr).find("th,td").map((_, td) => $(td).text().trim()).get();
    if (cols.length) rows.push(cols);
  });

  res.json({ url, rows });
});

app.listen(3000);

Checklist rápido pra você validar AGORA no seu caso

Se seu código faz response.json() e dá erro → não é JSON (use .text()).

Se no Postman funciona, mas no browser não → CORS (faça proxy no backend).

Se o HTML vem e você “não acha” a tabela → decode latin1 antes de parsear.

Confirme que você está mandando os mesmos parâmetros que o site manda (incluindo consultar=Consultar quando necessário).
